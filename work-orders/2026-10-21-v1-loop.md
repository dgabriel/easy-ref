# Work order: easy-ref v1, the builder/reviewer loop

The owner currently relays every step by hand between a builder agent (Codex) and a reviewer agent (Claude Code): work order, build, hand-back, independent re-check, review, fix order, repeat, approve. easy-ref automates the relaying. The owner is called in only for decisions that are theirs, and when the work is done.

A reviewing agent wrote this order and will gate each step. Push back in writing on anything you disagree with; don't silently skip it.

## Setup

- Branch `codex/v1-loop` from `main`. Local commits only; don't push or open a PR.
- Follow AGENTS.md. Python 3.11+, standard library only.
- Before writing code, reply with a short design note: module layout, the adapter interface, the verdict format, and the run-state layout. **Wait for the reviewer's OK before step 2.**

## What v1 does

```
easy-ref run <work-order.md> --builder codex --reviewer claude [--repo PATH]
easy-ref status [<run-id>]
easy-ref answer <run-id> "<owner decision>"      # resumes a run stopped for the owner
easy-ref stop <run-id>
```

One run, per round:

1. **Isolate.** On the first round, create a git worktree on a new branch `ref/<order-slug>` from the target repo's current HEAD. Never run an agent in the owner's checkout. Refuse to start if that branch or worktree already exists.
2. **Build.** Run the builder adapter in the worktree. Its prompt is the work order, plus the previous review's required fixes on later rounds. The builder commits locally and ends with a hand-back.
3. **Check.** easy-ref runs the configured check commands in the worktree itself and records exit codes and output. It never trusts the builder's report of them. If checks fail, skip the review. The failure output becomes the next round's required fixes and counts as a round.
4. **Review.** Run the reviewer adapter read-only in the worktree. Its input is the order, the diff since the run's base commit, the hand-back, and easy-ref's own check results. It must return a verdict (format below).
5. **Verify the reviewer.** If the worktree changed during review (`git status --porcelain` or HEAD differs), stop with `NEEDS_OWNER`.
6. **Decide.**
   - `APPROVE`: stop as done.
   - `CHANGES_REQUIRED`: start the next round.
   - `NEEDS_OWNER`: stop and show the question.

## Verdict format

The reviewer's final output is JSON with these fields:

```json
{"verdict": "APPROVE | CHANGES_REQUIRED | NEEDS_OWNER",
 "summary": "...",
 "required": [{"id": "R1", "what": "...", "evidence": "..."}],
 "owner_question": "... (NEEDS_OWNER only)"}
```

- Use the harness's structured-output option where one exists. Otherwise parse the last fenced JSON block.
- Validate it strictly. Missing, invalid, or ambiguous output is `NEEDS_OWNER` with the reason. **It is never approval.**
- `APPROVE` with failing checks is also `NEEDS_OWNER`.

## Stop conditions

The run stops and notifies the owner when:

- the work is approved, or
- a verdict is `NEEDS_OWNER`, or
- the round limit is reached (default 3), or
- the builder makes no new commit in a round, or
- the same required finding (same `what` text) appears in two consecutive reviews, or
- an adapter crashes, exits non-zero, or times out (configurable, default 30 minutes per agent call), or
- the owner runs `easy-ref stop`.

Each stop writes a short summary: the stop reason, rounds run, branch, final check results, and the owner question if there is one. Notify with a macOS notification (`osascript`); if that isn't available, print to the terminal. Keep the notifier pluggable.

`easy-ref answer` appends the owner's decision to the next builder prompt and resumes. If the question was the reviewer's, it resumes with a review instead.

## Adapters

Use one small interface for all harnesses. It takes the role (builder or reviewer), a prompt, the worktree path, a run directory for logs, and a timeout. It returns the exit code, the final message, and the log path. Adding a harness should mean adding one file, plus a config entry.

Verify every flag below from the installed CLI's `--help` before using it, and record the versions you checked. Don't trust this list blindly.

| Harness | Headless | Builder permissions | Reviewer, read-only |
| --- | --- | --- | --- |
| Codex CLI | `codex exec` | `--sandbox workspace-write`, `-C <worktree>` | `--sandbox read-only`; `--output-schema` for the verdict |
| Claude Code | `claude -p` | an edit-capable permission mode limited to the worktree | disallow edit and write tools; use a JSON or structured output option if available |
| Pi | `pi -p` | **no sandbox:** require explicit opt-in (`--allow-unsandboxed`) and say so in the run summary | an allowlist of read-only tools via `--tools`; it still has no sandbox, so step 5 matters |

Don't use flags that bypass approvals or sandboxes (for example `--dangerously-bypass-approvals-and-sandbox`) anywhere.

## Configuration

Put an optional `easy-ref.toml` in the target repo, read with `tomllib`. It holds:

- builder and reviewer adapters, and each one's model
- check commands
- the round limit and timeouts
- the notifier

CLI flags override the file. With no config, use the defaults above and no checks, and warn that nothing independent was verified.

## Run state

- Store run state outside tracked files: under the target repo's git directory (`<git-dir>/easy-ref/runs/<run-id>/`).
- Save per round: the prompts, adapter logs, hand-back, check output, and verdict JSON. Add a `run.json` holding the state machine status, so `status` and `answer` work after a restart.
- Nothing from a run is committed to the target repo automatically. The exception is work orders: if the target repo has `work-orders/`, write each `CHANGES_REQUIRED` review there as an order, and tell the builder to commit it with its fix. This matches the owner's existing convention.

## Tests

- Unit-test the loop with a scripted fake adapter. Cover:
  - approve on round 1
  - changes then approve
  - failing checks feeding back to the builder
  - malformed verdict → `NEEDS_OWNER`
  - reviewer modifies files → `NEEDS_OWNER`
  - approve while checks fail → `NEEDS_OWNER`
  - no new commit → stop
  - repeated finding → stop
  - round limit
  - timeout
  - answer-and-resume
  - existing branch refused
- Use temporary git repos. No real model calls in tests.
- Add `python3 -m unittest` as the check command in easy-ref's own `easy-ref.toml`.
